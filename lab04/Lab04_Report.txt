1. The Deadlock :
สาเหตุที่เกิด "Circular Wait" การรอกันเป็นวงกลม เป็นเพราะ Model A ล็อก GPU 0 เอาไว้แล้วกำลังไปรอคิวขอ GPU 1 ในขณะเดียวกัน Model B ก็ดันล็อก GPU 1 เอาไว้แล้วมารอคิวขอ GPU 0 กลายเป็นว่าต่างฝ่ายต่างถือของที่อีกคนต้องการเอาไว้ แล้วก็ไม่ยอมปล่อย ระบบเลยค้างรอกันไปมาอย่างไม่มีที่สิ้นสุด

2. The Solution :
การแก้โค้ดให้ Model B ต้องมาขอ GPU 0 ก่อน เป็นการทำลายวงจร Circular Wait เพราะมันคือการสร้างกฎว่าทุกคนต้องต่อคิวทรัพยากรตามลำดับเดียวกัน ดังนั้นใครก็ตามที่ชิงล็อก GPU 0 ได้ก่อน สมมติว่าเป็น Model A ก็จะได้สิทธิ์ไปล็อก GPU 1 ต่อจนทำงานเสร็จ ทำให้ไม่เกิดการไขว้กันล็อกคนละอันแบบในตอนแรก

3. Starvation vs Deadlock : 
- ความต่าง: ตอนเกิด Deadlock โปรแกรมจะค้างสนิทและหยุดทำงานไปเลย แต่ผลลัพธ์ของ Starvation โปรแกรมยังรันได้ปกติ เพียงแต่ Polite_Model โดนแย่งคิวจนแทบไม่ได้ทำงาน ได้ทำแค่หลักร้อยครั้ง เทียบกับตัว Greedy ที่ได้ทำเป็นหมื่นครั้ง
- วิธีแก้ด้วย Aging: ระบบ Process Scheduler สามารถแก้ปัญหานี้ได้ด้วยเทคนิค "Aging" คือการค่อยๆ เพิ่มระดับความสำคัญ (Priority) ให้กับ Polite_Model เรื่อยๆ เมื่อมันรออยู่ในคิวนานเกินไป จนสุดท้ายความสำคัญมันจะสูงพอที่จะแทรกคิวพวก Greedy เข้าไปใช้งาน CPU ได้อย่างยุติธรรม

4. Deadlock Detection & Recovery :
- การจำลอง Detection: พารามิเตอร์ 'timeout' ทำหน้าที่เหมือนตัวจับเวลาของ OS ถ้าระบบเห็นว่า Model A รอขอ GPU 1 นานเกิน 2 วินาทีโดยไม่ได้ของสักที ระบบก็จะตั้งข้อสงสัยแล้วว่าน่าจะเกิด Deadlock ขึ้น
- ขั้นตอน Recovery: เมื่อตรวจเจอ Deadlock แล้ว Model A ได้ทำการกู้คืนระบบ (Recovery) โดยการยอมปล่อย (release) GPU 0 ที่ตัวเองล็อกไว้ออกมา พอปล่อยปุ๊บ Model B ที่รอ GPU 0 อยู่ก็สามารถเอาไปทำงานต่อจนจบได้ ระบบเลยหลุดจากการติดล็อกตาย
